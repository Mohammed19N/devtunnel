Docs / Webhooks

Debug Stripe, GitHub and Shopify webhooks locally

A webhook provider needs a public URL to deliver events to. Passway gives your local app one, and the inspector keeps a copy of every delivery so you can replay it while you fix your handler.

The workflow Stripe GitHub Shopify Signatures and replay

The workflow

  1. Start your app locally, for example on port 3000.
  2. Open a tunnel: 
    passway http 3000
    Your account's default subdomain stays the same every time, so you register the URL with the provider once. On Pro you can reserve more names in the dashboard and pick one with --name. Names that contain a provider's brand, such as stripe-hooks, are refused.
  3. Register https://<your-subdomain>.{{.Host}}/your/webhook/path with the provider.
  4. Trigger an event. It appears in the inspector at localhost:4040 with the full headers and body, next to your app's response.
  5. Change your handler and press Replay to send the same delivery again, without triggering a new event at the provider.

Webhook deliveries are not browser page loads, so the Free plan's browser warning page never gets in their way.

Stripe

  1. In the Stripe Dashboard, in test mode, open Developers → Webhooks and add an endpoint with your tunnel URL, for example https://<your-subdomain>.{{.Host}}/webhooks/stripe.
  2. Select the events you handle and copy the endpoint's signing secret (whsec_…) into your app's configuration.
  3. Trigger an event, for example by completing a test checkout. The delivery shows up in the inspector with its Stripe-Signature header.

Stripe's official libraries reject a signature whose timestamp is older than their tolerance, five minutes by default. A replay keeps the original timestamp, so replay within that window or raise the tolerance in development.

GitHub

  1. In your repository, open Settings → Webhooks → Add webhook.
  2. Set the payload URL to your tunnel URL, for example https://<your-subdomain>.{{.Host}}/webhooks/github, the content type to application/json, and a secret.
  3. Choose the events and save. GitHub sends a ping event straight away, which you will see in the inspector.

GitHub signs the body with your secret in the X-Hub-Signature-256 header. The signature does not include a timestamp, so a replay verifies at any time.

Shopify

  1. For a store, open Settings → Notifications → Webhooks in the Shopify admin and create a webhook with your tunnel URL. For an app, add the URL to the webhook subscriptions in your app's configuration.
  2. Choose JSON as the format and the topic you handle, for example order creation.
  3. Use Send test notification or create a test order. The delivery appears in the inspector with its X-Shopify-Hmac-Sha256 and X-Shopify-Topic headers.

Shopify computes the HMAC over the raw body. Verify it against the bytes you received, before parsing the JSON.

Signatures and replay

Replay resends the captured request byte for byte, headers included, so signature checks pass the same way they did for the original delivery (subject to any timestamp tolerance). Edit & Replay changes the request, so a signature over the body will no longer match: use it to test how your handler rejects bad signatures, or turn verification off locally while you experiment.

The inspector stores up to 1 MB of each body. A delivery with a larger body is marked truncated and has to be edited before it can be replayed.
